# 技术适配手册

## 1. 技术栈

| 部分 | 技术 | 版本要求 |
| --- | --- | --- |
| 前端 | Next.js + React + Tailwind CSS + TypeScript | Node.js 18+ |
| 后端 | Python + FastAPI | Python 3.10+（推荐 3.12） |
| 包管理 | 后端 uv，前端 npm | — |
| 视频拼接 | ffmpeg | 需单独安装 |
| 配音（一键流水线） | edge-tts | 随依赖自动安装 |
| 部署 | 本地运行 / Docker Compose | — |

## 2. 目录结构

```
wanxiang-studio/
├── backend/
│   ├── api/              接口（路由）
│   ├── core/
│   │   ├── orchestrator.py   流程调度（状态机）
│   │   ├── scenarios.py      场景包加载
│   │   ├── stages.py         6 种内置阶段
│   │   └── agents/           每个阶段的执行程序
│   ├── scenarios/        ★ 场景包（每个子目录是一个产品）
│   ├── prompts/          默认提示词
│   ├── models/           各服务商的调用代码
│   ├── registry/         模型注册表
│   ├── pipelines/        一键流水线
│   ├── config.py         配置加载
│   └── config.yaml       配置文件（Key 存这里，不提交 git）
├── frontend/
│   ├── app/              页面：首页、设置、沙盒、流水线
│   ├── components/       组件（stages/ 下是 6 个阶段的界面）
│   └── config/brand.ts   品牌名称
├── docs/                 官方文档
└── scripts/              安装、启动、新建场景脚本
```

## 3. 运行与部署

### 本地运行

```bash
# 后端
cd backend && uv sync --python 3.12 && uv run python api_server.py
# 前端（另开终端）
cd frontend && npm install && npm run dev
```

| 服务 | 默认地址 | 本机实际地址 |
| --- | --- | --- |
| 前端 | http://localhost:3000 | http://localhost:3001（3000 被其他项目占用） |
| 后端 | http://localhost:8000 | http://localhost:8001（8000 被其他项目占用） |

本机通过 `AIGC平台/.claude/launch.json` 启动，用环境变量改端口，项目代码没有改动。

### Docker

```bash
cp .env.example .env   # 填入 Key
docker compose up --build
```

### 注意

- 一键安装脚本 `scripts/install.sh` 检查的是系统自带的 Python。本机系统 Python 是 3.9，会报错，需要手动安装。
- `scripts/dev.sh` 固定使用 8000 / 3000 端口，在本机会和其他项目冲突。

## 4. 配置

### 加载顺序（后面的覆盖前面的）

```
config.py 默认值  →  backend/config.yaml（设置页写入这里）  →  SFA_* 环境变量（只在运行时生效）
```

### config.yaml 结构

| 段 | 内容 |
| --- | --- |
| `app` | 产品名、标语 |
| `server` | 地址、端口、日志级别 |
| `api_providers` | 各服务商的 Key、接口地址、是否走代理 |
| `models` | 每个环节的默认模型 |
| `generation` | 默认风格、比例、分辨率、视频模式 |
| `workflow` | 默认场景、全局替换阶段程序 |
| `custom_models` | 额外登记的模型 |

### 常用环境变量

| 变量 | 作用 |
| --- | --- |
| `SFA_PORT` / `SFA_HOST` | 后端端口 / 地址 |
| `SFA_<服务商>_API_KEY` | 服务商 Key，如 `SFA_DASHSCOPE_API_KEY` |
| `SFA_MODEL_<环节>` | 默认模型，如 `SFA_MODEL_LLM` |
| `SFA_DEFAULT_SCENARIO` | 默认场景 |
| `SFA_CORS_ORIGINS` | 允许访问后端的前端地址（改前端端口时要加） |
| `SFA_PROXY` | 代理地址 |
| `BACKEND_API_URL` / `NEXT_PUBLIC_API_URL` | 前端连接的后端地址（前端用） |
| `NEXT_PUBLIC_APP_NAME` | 前端显示的产品名 |

## 5. 接口（API）

无需登录。完整说明见 `docs/api.md`。

### 主流程

| 接口 | 作用 |
| --- | --- |
| `POST /api/project/start` | 创建项目 |
| `POST /api/project/{id}/execute/{stage}` | 执行某个阶段 |
| `GET /api/project/{id}/status` | 查询进度 |
| `GET /api/project/{id}/artifact/{stage}` | 获取阶段产物 |
| `POST /api/project/{id}/artifact/{stage}/upload_image` | 上传图片替换产物 |
| `POST /api/project/{id}/intervene` | 提修改意见 |
| `POST /api/project/{id}/continue` | 确认，进入下一阶段 |
| `POST /api/project/{id}/stop` | 停止 |

### 其他

| 接口 | 作用 |
| --- | --- |
| `GET /api/scenarios`、`POST /api/scenarios/reload` | 场景列表、不重启重新加载场景 |
| `GET /api/sessions`、`DELETE /api/sessions/{id}` | 历史项目 |
| `GET / PUT /api/config` | 读取 / 保存配置 |
| `GET /api/models` | 模型列表 |
| `POST /api/sandbox/{llm,vlm,t2i,i2i,video}` | 沙盒单模型测试 |
| `POST /api/pipelines/{standard,digital_human,action_transfer}/tasks` | 一键流水线 |
| `GET /api/tasks/{id}/events` | 实时进度推送 |
| `POST /api/upload_file`、`/api/upload_media` | 上传文件 |
| `GET /api/health` | 健康检查 |

## 6. 数据存储

| 数据 | 位置 |
| --- | --- |
| 项目（会话） | `backend/code/data/sessions/{id}.json` |
| 生成的图片 / 视频 | `backend/code/result/`，通过 `/code/*` 访问 |
| 配置和 Key | `backend/config.yaml` |

无数据库、无对象存储、无用户表。

## 7. 扩展点（从易到难）

| 需求 | 改哪里 | 难度 |
| --- | --- | --- |
| 新增行业场景 | `python3 scripts/new-scenario.py <id> --from <已有场景> --name <名称>`，再改 `scenario.yaml` 和 `prompts/` | ⭐ 不用写代码 |
| 只改某个场景的提示词 | `scenarios/<id>/prompts/` 下放同名文件覆盖 | ⭐ |
| 改所有场景的提示词 | `backend/prompts/` | ⭐ |
| 换品牌 | `config.yaml` 的 `app.name`、前端 `NEXT_PUBLIC_APP_NAME` | ⭐ |
| 换 / 加模型 | 见《模型适配手册》 | ⭐–⭐⭐⭐ |
| 某个场景加自定义阶段 | 场景包写 `agents.py`，继承 `AgentInterface` | ⭐⭐⭐ 要写代码 |
| 全局替换某个阶段的程序 | `config.yaml` → `workflow.agents` | ⭐⭐⭐ |
| 外部 Agent 调用 | `integrations/agent-skill/` | ⭐⭐ |

### 场景包硬性规则

- 文件夹名就是场景 id，用英文小写加下划线。
- 阶段有先后依赖：分镜需要剧本，参考图需要分镜，视频需要参考图，后期需要视频。
- 覆盖提示词时，只能使用原文件里已有的 `{占位符}`。
- 剧本提示词必须保留固定格式（`## 第N集`、场次标题、`人物：`行、台词行），否则分镜解析不了。
- 改完场景后跑检查：`cd backend && uv run --extra dev pytest tests/test_scenarios.py`

## 9. 上线前必须补的（当前缺失）

| 缺失 | 风险 |
| --- | --- |
| 登录鉴权 | 接口完全公开，任何人能调用，消耗你的 Key 额度 |
| 数据库 | 用文件存数据，多人同时用会出问题 |
| 对象存储 | 图片和视频堆在本地磁盘 |
| Key 管理 | Key 明文存在 `config.yaml` |
| 任务队列 | 长时间生成任务直接占用服务进程 |
| 依赖漏洞 | 前端依赖有 16 个已知漏洞（含 1 个严重） |
