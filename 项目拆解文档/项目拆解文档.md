# 万象工场 项目拆解

## 一句话定位

一个 **AIGC 内容生产底座**：用户输入一句需求 → 系统按多个阶段依次生成 → 每个阶段人工确认 → 产出视频或图片。
换一个“场景包”，就是另一个行业产品。

---

## 一、产品架构

### 1. 核心概念（只需记住 3 个）

| 概念 | 是什么 | 类比 |
| --- | --- | --- |
| **场景包** | 一个文件夹 = 一个行业产品。规定有哪些步骤、默认参数、首页文案、提示词 | 一份“菜谱” |
| **阶段** | 生产流程中的一步，如写剧本、画分镜 | 菜谱里的一道工序 |
| **人在回路** | 每个阶段完成后暂停，用户可查看、修改、重新生成，确认后才进入下一步 | 每道工序做完先尝一口 |

### 2. 生产流程（6 个阶段）

```
需求 → ① 剧本 → ② 角色/场景设定 → ③ 分镜 → ④ 画面 → ⑤ 视频片段 → ⑥ 剪辑成片
         ↑ 每一步后都暂停，等用户确认
```

| # | 阶段 | 产出 | 用到的 AI |
| --- | --- | --- | --- |
| 1 | 剧本生成 | 分集剧本 | 大语言模型 |
| 2 | 角色 / 场景设计 | 角色、场景、商品的设定图 | 大语言模型 + 图片模型 |
| 3 | 分镜 | 每个镜头的画面描述 | 大语言模型 |
| 4 | 参考图生成 | 每个镜头的画面 | 图片模型 |
| 5 | 视频生成 | 每个镜头的视频片段 | 视频模型 |
| 6 | 后期 | 拼接成完整成片 | ffmpeg（非 AI） |

### 3. 内置 5 个场景（= 5 个产品）

| 场景 | 输入 | 产出 | 阶段数 |
| --- | --- | --- | --- |
| AI 短片 | 故事灵感 | 多集剧情短片 | 6 |
| 电商广告片 | 商品 + 卖点 | 30–45 秒竖屏带货视频 | 6 |
| 漫剧 | 世界观 + 主角 | 竖屏多集漫画短剧 | 6 |
| 旅游宣传片 | 目的地 + 卖点 | 45–60 秒宣传片 | 6 |
| 商品海报 | 商品 + 卖点 | 3–4 张电商海报 | 4（不做视频） |

**结论：5 个产品共用同一套引擎，区别只在场景包里的配置和提示词。**

### 4. 其他功能入口

| 功能 | 说明 |
| --- | --- |
| 设置页 | 填 API Key、选每个环节用哪个模型 |
| 一键流水线 | 不需要逐步确认的快捷流程：文艺短视频、数字人口播、动作迁移 |

## 二、技术实现

### 1. 整体结构

```
 浏览器
   │
 ┌─▼──────────────┐
 │ 前端（网页界面）  │  Next.js + React
 └─▼──────────────┘
   │  接口请求
 ┌─▼──────────────────────────────┐
 │ 后端（业务逻辑）                  │  Python + FastAPI
 │                                 │
 │  编排器：按场景包的阶段顺序调度      │
 │     ↓                           │
 │  阶段 Agent：每个阶段一个“AI 员工”  │
 │     ↓                           │
 │  模型门面：统一调用各家 AI 服务     │
 └─▼──────────────────────────────┘
   │
 外部 AI 服务：阿里百炼 / 火山方舟 / 可灵 / OpenAI / Gemini / DeepSeek
```

### 2. 各层分工

| 层 | 作用 | 技术 | 位置 |
| --- | --- | --- | --- |
| 前端 | 页面展示、用户操作 | Next.js 16、React 19、Tailwind | `frontend/` |
| 接口层 | 接收前端请求 | FastAPI | `backend/api/` |
| 编排器 | 流程总调度：决定现在做哪一步、暂停、继续、保存进度 | Python 状态机 | `backend/core/orchestrator.py` |
| 场景包 | 定义每个产品的步骤和提示词 | YAML 配置 + 文本提示词 | `backend/scenarios/` |
| 阶段 Agent | 干活的“AI 员工”，每阶段一个 | Python | `backend/core/agents/` |
| 提示词 | 告诉 AI 怎么写、怎么画 | 文本文件 | `backend/prompts/` |
| 模型门面 | 统一入口，按配置自动转给对应的 AI 服务商 | Python | `backend/models/` |
| 模型注册表 | 登记“哪个模型属于哪家、能做什么” | YAML | `backend/registry/models.yaml` |
| 配置 | API Key、默认模型 | YAML | `backend/config.yaml` |

### 3. 默认用的模型

| 环节 | 模型 | 服务商 |
| --- | --- | --- |
| 文本（剧本、分镜） | 通义千问 qwen3.5-plus | 阿里百炼 |
| 图片 | 万相 wan2.7-image | 阿里百炼 |
| 视频 | 万相 wan2.7 | 阿里百炼 |

可在设置页切换，不用改代码。

### 4. 数据存在哪

| 数据 | 位置 | 格式 |
| --- | --- | --- |
| 项目进度（会话） | `backend/code/data/sessions/` | JSON 文件 |
| 生成的图片、视频 | `backend/code/result/` | 图片 / 视频文件 |

**结论：没有数据库、没有用户系统，所有数据都是本地文件。适合教学和原型，不能直接当线上产品用。**

## 三、二次开发：改哪里

| 想做的事 | 改哪里 | 要写代码吗 |
| --- | --- | --- |
| 新增一个行业场景 | 复制一个场景包，改 `scenario.yaml` 和提示词 | 不用 |
| 调整生成效果 | 改场景包里的提示词 | 不用 |
| 换模型 | 设置页切换 | 不用 |
| 换产品名 / 品牌 | `frontend/config/brand.ts` | 改一行配置 |
| 加一个全新的阶段 | 在场景包里写自定义 Agent | 要 |
| 接入新的 AI 服务商 | `backend/models/` | 要 |

**结论：产品经理的主要工作是“写场景包 + 调提示词 + 验收效果”，大部分不用写代码。**
